# 多标动态选股 Agent 汇报

> 聚焦多标（动态选股）路径。单标 8 节点图不在本汇报范围。

## 1. 目标

让 LangGraph 成为多标模式的**唯一执行路径**，把 TopDown 的「板块 → 个股 → 权重」逻辑变成图节点，并在 A 股全市场动态股票池上用「板块相对强度」选股，可选 deepseek LLM 做阶段决策。

## 2. 架构：多标 LangGraph 拓扑

`TradingAgentsGraph` 类持有两张编译图，单标图与多标图并存、互不干扰：

```
START → universe → [cond] → sector_selector → stock_selector → allocator → END
                   └→ END（空 universe/candidates 时）
```

| 节点 | 职责 | 产出 state |
|---|---|---|
| `_universe_node` | 加载动态股票池 + 价格/技术指标 overlay + 预筛选 | `market_snapshot` `prices` `technical_context` |
| `_sector_selector_node` | 板块相对强度排序选 top-N 行业 | `selected_sectors` + `sector_view` 部分 |
| `_stock_selector_node` | 选中行业内按相对强度选龙头 + softmax 权重 | `sector_view.selected_stocks` |
| `_allocator_node` | 趋势感知现金储备 + 单仓上限 → 目标持仓 | `target_positions` |
| `_route_after_universe` | 空 universe → END，否则继续 | 路由串 |

- 重对象（candidates DataFrame、selected_stocks DataFrame）走运行时属性，不进 state 序列化，避免 checkpoint 体积膨胀。
- checkpointer 用 `JsonPlusSerializer(allowed_msgpack_modules=...)`，allowlist 为 `(模块, 类名)` 元组格式（字符串格式在 base=True 时是 no-op，会漏注册）。
- `run_multi` 有 TypeError → 无 checkpointer 兜底编译路径，保证 MemorySaver 不可用时仍能跑。

## 3. 数据层：动态 universe + 真行业标签

`_resolve_dynamic_universe` 按 `dynamic_min_turnover` 过滤全市场，取 top-N 高流动股。

**关键问题**：本机网络下 eastmoney 的行业板块接口（`stock_board_industry_name_em` / `stock_board_industry_cons_em`）被 RemoteDisconnected block。直接 fallback 到 Sina 全市场 spot，但 Sina 无行业列，若用 symbol 前缀分「沪市主板/创业板」等**交易所板块**，则「板块相对强度」选的是交易所而非行业——策略失效。

**修复**：用申万一级成分股建全市场 `symbol → 申万行业` 映射（`sw_index_first_info` + `index_component_sw(symbol='801010'` 不带 `.SI` 后缀`)），Sina spot 的 sector 字段填真行业（电子/通信/银行/电力设备…）。映射进程级缓存，避免每次 reset 重建。

```
Sina spot (5532 股, change_pct 百分点→÷100 小数)  +  申万一级成分股映射  →  带真行业的 universe
```

单位坑：Sina `涨跌幅` 是百分点（1.877 = 1.877%），系统其他地方（benchmark_return、engine return_1d）用小数，须 ÷100 统一，否则当 `return_1d` overlay 缺失时板块 RS 单位错位 100 倍。

## 4. 选股策略：板块相对强度优先

旧逻辑：板块按 `avg_factor_score`（含 0.25 流动性权重）排序，个股按 factor_score softmax——流动性优先，偏高流动大票，在科技下跌月跑输基准。

新逻辑（流动性降为门槛，不再进打分）：

- **板块相对强度** `RS_sector = avg_change - benchmark_return`，跑赢基准的行业优先；普跌日取相对最强 top-N。
- **个股 relative_strength** `= zscore(动量) + zscore(趋势)`，板块内按此排名选龙头（`groupby(sector).head(N)`）。
- **factor_score** 权重改为 动量 0.45 / 趋势 0.35 / 波动率 0.20 / 流动性 0.0。
- **softmax 权重**用 `relative_strength`，不再用含流动性的 factor_score。
- **防御过滤**：非看涨市场只留 `relative_strength > 0` 的票。
- **趋势感知现金**：bearish +0.60 / neutral +0.35 / bullish 0.0，cap 0.75。

## 5. deepseek LLM 多阶段决策 + 容错

6 个 LLM 阶段：`market_regime → sector_selector → stock_selector → candidate_analyst → bull_bear_research → portfolio_manager`。

- **model 解析**：`BacktestConfig.llm_model` 默认 `gpt-4o`，显式传给 LLMClient 会覆盖 .env 的 deepseek-v4-flash → 全 400 降级。修复：LLMClient 把 OpenAI 占位名视为未配置，回退读 `OPENAI_MODEL/OPENAI_DEEP_MODEL`。
- **hang 兜底**：langchain `timeout` kwarg 对底层 httpx 不总生效，deepseek 偶发 hang 会卡死回测。修复：`ThreadPoolExecutor` 包 `chain.invoke` + `future.result(timeout)`，超时降级返回 None；timeout 降级后不再走 SDK fallback（同 endpoint 同样 hang）。
- **阶段失败降级**：`_complete_stage` 失败记录到 `_llm_stage_errors` 并返回 None，调用方走规则 fallback，单次失败不沉整轮回测。
- **trace**：`llm_trace.model_used` 取 `self.llm.deep_model`（解析后值），不再误显示 `gpt-4o`。

## 6. 实验结果

### 6.1 行业映射修复前后

| | sector 字段 | 选中示例 |
|---|---|---|
| 修复前 | 沪市主板/创业板（交易所） | 策略失效 |
| 修复后 | 电子/通信/电力设备（申万行业） | RS 可正确排序 |

### 6.2 RS 策略跌涨段对比（同 universe 防守15%）

> ⚠️ **基准数据更正（2026-07-28）**：此前 000300 裸代码未被指数端点识别，回退到 synthetic 随机数据，导致 924 段基准被低估（旧值 +8.58%，实际 +32.47%）。以下已用真实基准重算。

| 行情段 | 总收益 | 基准 | 超额 |
|---|---|---|---|
| 2024-01 科技跌 | -6.52% | +6.76% | -13.28% |
| 2024-09~10 924 暴涨 | +5.30% | **+32.47%** | **−27.17%** |

RS 是顺势策略，跌段跑输是 universe 偏科技 + 行情错配，非策略缺陷。924 V 型急涨段趋势信号形成滞后，RS 低配/未配导致大幅跑输。

## 7. 前端可视化

多标模式 `sector_view` 面板：市场观 / 基准当日 / 行业相对强度排名 / 选中行业（字符串数组）/ 个股权重 / aggregate_weight_reasoning / llm_trace。NaN 清洗（`_sanitize_records`）保证 JSON 安全。空 `{}` 渲染提示，部分 dict 报错。

实时选股推荐（`/api/state`）：拉当天全市场 spot + 申万行业 + RS 策略，输出 `target_positions`（symbol → 股数）+ `sector_view`。
