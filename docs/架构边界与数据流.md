## 1. 文档目的

本文档描述当前代码真实存在的模块、依赖和数据流，并规定后续架构重构必须保持的外部行为。它是成员 A 后续 A-02 至 A-08 的实施边界，也是成员 B/C/D 并行开发时的接口和文件所有权依据。

本文档不声称当前系统已经完成解耦。凡标记为“后续阶段”的内容均是明确的实施入口，不是已经存在的代码。

## 2. 不变量

成员 A 的架构提交必须始终满足以下条件：

1. 不改变单标或多标模式的交易决策语义。
2. 不改变因子公式、阈值、仓位限制、Prompt 或 LLM 输出解释方式。
3. 不改变 LangGraph 节点名称、边、条件路由或 checkpoint 行为。
4. 不改变 `/api/*` 路径、请求字段和现有响应字段。
5. 不改变手续费、滑点、A 股整手约束和卖单优先顺序。
6. 不让历史回测、测试替身或离线模式意外访问在线 LLM。
7. 不提交密钥、`.env`、运行期记忆或临时缓存。

若后续需求必须打破任一不变量，必须另建任务，由相关负责人共同确认，不能混入架构重构提交。

## 3. 当前模块边界

### 3.1 接入层

主要文件：`app.py`、`index.html`、`app.js`、`styles.css`。

职责：提供静态页面；将 HTTP 请求转换为 `MarketEnv` 调用；返回 JSON 响应并统一捕获接口异常。

当前公开 HTTP 路径：

```text
GET  /api/state
GET  /api/report
GET  /api/quote
GET  /api/live/quote
GET  /api/paper/account
POST /api/reset
POST /api/step
POST /api/run
POST /api/paper/order
POST /api/paper/rebalance
POST /api/paper/adjust
```

边界规则：接入层可以依赖应用门面，但不应直接依赖具体 Agent、数据提供器或模拟券商。前端由成员 D 负责；成员 A 不在架构提交中调整页面和接口展示。

### 3.2 应用门面

主要文件：`tools/market.py`。

职责：持有 `TradingBacktestEngine`；为 HTTP 层提供重置、推进、运行、报价、账户和手工交易接口；把 API 输入转换为 `BacktestConfig` 或引擎方法参数。

当前依赖：

```text
tools.market -> engine.backtest
tools.market -> core.schemas
```

边界规则：`app.py` 只通过门面使用回测能力。后续引擎拆分不得要求前端了解 Graph、Provider 或 Broker。

### 3.3 回测编排层

主要文件：`engine/backtest.py`。

当前职责：

- 根据配置创建数据提供器并加载基准、单标和多标行情。
- 构建动态股票池并补充指标。
- 管理回测日索引、再平衡周期和权益序列。
- 调用单标或多标 Graph。
- 把目标持仓转换为实际订单，按卖出优先顺序执行。
- 回填记忆结果。
- 汇总账户、基准、收益、回撤和报告。

当前直接依赖：

```text
engine.backtest -> agents.graph
engine.backtest -> core.schemas
engine.backtest -> data.providers
engine.backtest -> data.universe
engine.backtest -> tools.broker
engine.backtest -> tools.indicators
engine.backtest -> tools.sizing
```

已确认的耦合点：

- 构造函数内部直接创建 `TradingAgentsGraph`。
- `reset()` 会重新创建 Provider 和 Broker。
- 动态股票池获取、行情加载、执行和报告集中在同一类。
- 多标结果回填通过 `self.graph.memory` 穿透 Graph 边界。

后续落点：A-04 只处理依赖注入，A-05 处理股票池快照，A-06 处理订单规划。三个阶段必须独立提交并分别验证行为等价。

### 3.4 Agent 编排层

主要文件：`agents/graph.py`、`agents/state.py`、`agents/top_down.py`。

当前职责：编译单标与多标 LangGraph；调用分析师、研究辩论、风险与组合经理；维护 LLM、RAG、工具、记忆和知识库上下文；执行多标市场状态、行业、个股、辩论、组合与分配链路。

当前直接依赖：

```text
agents.graph
  -> agents.analysts
  -> agents.llm_client
  -> agents.memory
  -> agents.portfolio_manager
  -> agents.researchers
  -> agents.risk
  -> agents.state
  -> agents.top_down
  -> core.schemas
  -> tools.langchain_tools
  -> tools.news
  -> tools.rag
  -> tools.sizing
```

已确认的隐藏运行时状态：

```text
_runtime_frame
_runtime_llm
_runtime_candidates
_runtime_selected
top_down.experience_lesson
top_down.sentiment_context
top_down.knowledge_context
```

这些字段在多个节点之间传递数据，但没有完整进入 `TradingGraphState`。它们是后续显式化数据流的重点，同时涉及成员 D 对 State 和 Graph 编译的职责。成员 A 在未完成对接前不直接移除或改写这些字段。

### 3.5 领域模型层

主要文件：`core/schemas.py`。

职责：定义行情、组合、分析报告、交易意图、风险结果、组合决策、Graph 结果和 `BacktestConfig`，提供跨模块共享的数据模型。

边界规则：`core` 不得依赖 `agents`、`engine`、`data` 或 `tools`。新增跨层协议应放在 `core`，但不得把具体实现类或 pandas DataFrame 强制写入核心模型。

### 3.6 数据访问层

主要文件：`data/providers.py`、`data/universe.py`。

职责：从 synthetic、CSV、AkShare、Tushare 或 yfinance 获取行情；标准化证券代码和行情字段；获取 A 股行业、全市场快照和行业成分。

当前依赖：

```text
data.providers -> core.schemas
data.universe  -> 第三方数据源
```

边界规则：数据层返回标准化数据，不参与 Agent 决策。历史回测使用了何种股票池、何时获取、来自哪个数据源，必须能被记录和重放；A-05 才会实现相应快照对象和服务。

### 3.7 执行与基础能力层

主要文件：`tools/broker.py`、`tools/sizing.py`、`tools/indicators.py`、`tools/news.py`、`tools/fundamentals.py`、`tools/rag.py`、`tools/langchain_tools.py`。

职责：Broker 维护现金、持仓、成本和成交；Sizing 处理市场整手和订单数量约束；Indicators 生成确定性技术指标；News/Fundamentals/RAG/Tools 提供 Agent 所需上下文。

边界规则：基础能力可以依赖 `core.schemas`，不应反向创建回测引擎或 Graph。现存 `tools.market -> engine.backtest` 是应用门面例外，不代表其他工具可以依赖引擎。

### 3.8 持久化记忆层

主要文件：`agents/memory.py`。

职责：写入单标与多标 JSONL 决策记录；回填多标决策的区间超额收益；按市场形态和市场机制召回历史经验；将记录转换为 LangChain 对话历史或经验课程。

边界规则：记忆算法由成员 B 负责。架构层可以定义调用协议和隔离存储位置，但不得改变召回距离、样本门控和排序偏置。

## 4. 当前端到端数据流

### 4.1 初始化和重置

```text
HTTP /api/reset
  -> MarketEnv.reset(payload)
  -> BacktestConfig
  -> TradingBacktestEngine.reset(config)
  -> build_provider / dynamic universe
  -> load benchmark and symbol histories
  -> enrich_indicators
  -> SimulatedBroker(config)
  -> Graph.reconfigure_selector(config, universe_frame)
  -> serialized engine state
```

重置的可观察结果包括新的配置、行情窗口、空交易记录、初始权益和初始账户状态。后续依赖注入不得破坏这些行为。

### 4.2 单标决策

```text
MarketBar + enriched DataFrame + PortfolioSnapshot + BacktestConfig
  -> TradingAgentsGraph.run
  -> analyst team
  -> LangChain tools and RAG
  -> research debate
  -> hold OR trader
  -> optional risk debate
  -> risk committee
  -> portfolio manager
  -> PortfolioDecision
  -> SimulatedBroker.execute
  -> ExecutionFill
  -> TradingMemory.append
  -> report/state
```

关键不变量：研究结果为中性时进入 hold；可执行方向性订单经过风险链；Broker 最终拥有成交约束权。

### 4.3 多标决策

```text
current prices + technical context + market snapshot + PortfolioSnapshot
  -> TradingAgentsGraph.run_multi
  -> universe load and pre-filter
  -> K-line features / sentiment / experience recall
  -> market regime
  -> sector selector + knowledge recall
  -> stock selector
  -> candidate analyst
  -> debate ranker
  -> portfolio planner
  -> allocator
  -> target_positions {symbol: shares}
  -> engine position diff
  -> sells before buys
  -> SimulatedBroker.execute per symbol
  -> next rebalance back-fills active_return
```

关键不变量：Graph 输出绝对目标持仓，引擎负责与当前持仓求差；卖出订单先执行以释放现金；Broker 再次执行现金、持仓、费用和滑点约束。

### 4.4 报告流

```text
broker snapshot + equity history + benchmark bars + trades
  -> TradingBacktestEngine.report / to_dict
  -> MarketEnv
  -> /api/report or /api/state
  -> frontend
```

后续重构必须维持现有返回字段。若成员 D 需要新增字段，应采用向后兼容的增量方式。

## 5. 允许的依赖方向

目标依赖方向：

```text
接入层 -> 应用门面 -> 回测编排层 -> 核心协议与领域模型

回测编排层
  -> Agent runner 协议
  -> 行情/股票池协议
  -> Broker 与确定性基础能力

Agent 实现
  -> 核心领域模型
  -> 数据/工具抽象
  -> 记忆抽象

数据与工具实现 -> 核心领域模型
core -> Python 标准库 / Pydantic
```

禁止方向：

- `core -> engine/agents/data/tools`
- 数据提供器直接调用 Graph 或 Broker
- 前端直接导入 Agent 实现
- 记忆算法直接控制 Broker
- Prompt/因子模块直接修改回测引擎内部状态
