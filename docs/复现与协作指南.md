# 回测复现与团队协作指南

> 适用分支：`feat/member-a-architecture`
>
> 更新日期：2026-10-13
>
> 目标：让环境、输入、运行命令、结果和团队接口都可检查、可重放、可交接。

## 1. 复现范围

“可复现”需要区分三层：

1. 离线工程回归：固定代码、Synthetic 行情和确定性测试替身，验证模块接口与交易执行行为。
2. 股票池重放：保存 `UniverseSnapshot`，固定候选股票及其捕获元数据。
3. 正式策略实验：在前两项基础上，额外固定行情文件、日期、复权方式、模型、Prompt、依赖版本与实验配置。

`UniverseSnapshot` 只冻结股票池横截面，不会自动冻结每只股票的历史 K 线，也不会使在线 LLM 输出变成确定性结果。报告中不得把 `captured_at` 误写成历史成分股生效日期；只有数据源明确返回日期时，`as_of` 才表示上游日期。

## 5. 股票池快照捕获与重放

动态股票池服务输出带 SHA-256 内容标识的 `UniverseSnapshot`。正式回测应显式保存快照，不依赖下一次运行重新抓取实时市场。

捕获示例：

```python
from pathlib import Path

from core.schemas import BacktestConfig
from data.universe_service import DynamicUniverseService

config = BacktestConfig(
    provider="akshare",
    dynamic_universe=True,
    dynamic_universe_limit=30,
)
snapshot = DynamicUniverseService().capture(config)
snapshot.save(Path("path/to/run/universe.json"))
print(snapshot.summary())
```

重放示例：

```python
from core.schemas import BacktestConfig
from data.universe_service import UniverseSnapshot
from engine.backtest import TradingBacktestEngine

config = BacktestConfig(
    provider="akshare",
    dynamic_universe=True,
    dynamic_universe_limit=30,
)
snapshot = UniverseSnapshot.load("path/to/run/universe.json")
engine = TradingBacktestEngine(config, universe_snapshot=snapshot)
result = engine.run_to_end()
assert result["report"]["universe_snapshot"]["snapshot_id"] == snapshot.snapshot_id
```

若要做到完全离线的正式实验重放，还需注入固定 `MarketDataSource` 或保存对应日期范围的行情文件；只保存股票池快照不足以冻结行情。

## 6. 正式实验留档清单

每次进入报告或 PPT 的实验至少记录：

| 项目 | 最低要求 |
|---|---|
| 代码 | 分支、commit hash、工作区是否干净 |
| 环境 | Python 版本、依赖版本、操作系统 |
| 配置 | 完整 `BacktestConfig`，包括费用、滑点、仓位和再平衡参数 |
| 行情 | Provider、标的、起止日期、复权方式、数据文件或抓取时间 |
| 股票池 | 快照 JSON、snapshot ID、source、captured_at、as_of |
| 模型 | Agent 模式、模型名称、Base URL 域名；不记录密钥 |
| 输出 | 原始 report JSON、成交记录、权益曲线、测试结果 |
| 场景 | 急涨、反弹、杀跌、震荡的明确日期窗口和基准 |

实验文件命名应包含场景、日期和代码短哈希，避免用 `final2`、`new-final` 等无法审计的名称。

## 7. 成员 A 已交付的稳定接口

### 7.1 运行时协议

`core/contracts.py` 提供：

- `GraphRunner`：单标 `run`、多标 `run_multi`、结果回填和 selector 重配。
- `MarketDataSource`：历史行情、最新报价和标的信息。
- `UniverseSource`：全市场、行业和行业成分的标准化入口。

协议使用结构化类型。测试替身和新实现只需满足方法结构，不需要继承项目基类。

### 7.2 引擎依赖注入

```python
TradingBacktestEngine(
    config=None,
    provider=None,
    graph=None,
    universe_service=None,
    universe_snapshot=None,
)
```

- 不传参数时保持原默认构造行为。
- 注入 Provider 或 Graph 后，`reset()` 保留调用方提供的实例。
- 固定 `universe_snapshot` 优先于实时股票池服务。
- 注入的最小 Graph 不必暴露内部 `memory` 属性。

### 7.3 再平衡规划

```python
plan_rebalance_orders(current_positions, target_positions, config)
```

该函数只生成 `PortfolioDecision` 订单意图，不访问行情或 Broker，也不修改输入。它保持卖单优先，并复用既有 sizing 处理整手与清仓。现金、价格、费用、滑点和实际成交仍由 `SimulatedBroker` 决定。

### 7.4 公开输出

动态股票池模式下，`engine.to_dict()` 和 `engine.report()` 增量提供 `universe_snapshot` 摘要。非动态模式为 `null`。这是向后兼容的新增字段，前端可选择展示，但不应依赖完整快照记录出现在 API 中。

## 8. 团队文件边界

| 成员 | 负责范围 | 不应被其他成员顺手修改的核心文件/语义 |
|---|---|---|
| A | 架构协议、引擎解耦、快照、订单规划、架构文档 | `core/contracts.py`、`engine/rebalance.py`、注入与快照接口 |
| B | 记忆样本门控、召回偏置 | `agents/memory.py` 的门控、距离、排序和写入语义 |
| C | Prompt、JSON 容错、行业 RS、质量因子、回测与消融 | Prompt、因子公式、实验脚本和正式结果 |
| D | `TradingGraphState`、Graph 编译、前端与 PPT | `agents/state.py`、Graph 节点/边、HTML/CSS/JS |

共享文件修改前先在 `log/handoffs.md` 登记。发生冲突时保留功能负责人的语义，通过公开接口适配，不复制第二套相似逻辑规避冲突。

## 9. 推荐合并顺序

1. 先合并成员 A 的 A01–A08 架构提交，建立协议、注入、快照和回归安全网。
2. 成员 B、C 分别 rebase 到该基线；二者文件不冲突时可独立合并，每次合并后跑全量测试。
3. 成员 D 在 A 的 `GraphRunner` 边界上接入最终 State/Graph；若同时消费 B/C 输出，放在 B/C 之后合并。
4. 最后统一处理 README/报告/PPT 的事实同步，执行全量测试、四场景回测和浏览器冒烟。
5. 未经负责人确认，不把冲突解决、格式化全仓库或参数调优混入某个成员的功能提交。

推荐每个逻辑目标一个 commit；提交前执行：

```powershell
git diff --check
git diff --stat
git status --short
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -v
```

## 10. 已知边界与后续负责人

- 在线 LLM 具有供应商、模型版本和采样不确定性；收益比较必须保留原始输出和模型信息。负责人：C。
- 股票池快照不等于行情快照；正式历史复现需补齐固定行情输入。负责人：C，A 提供注入接口。
- 记忆门控和近期/相似行情偏置由 B 调整，A 的测试不冻结其数值。
- Graph 隐藏运行时字段、最终 State 和编译拓扑由 D 完善，需保持 `GraphRunner` 入口兼容。
- 前端展示由 D 维护；新增后端字段优先采用向后兼容方式。
- A 股数据源可能受网络、限流、停牌与历史窗口缺失影响；正式结果需记录被跳过的标的和数据源错误。
